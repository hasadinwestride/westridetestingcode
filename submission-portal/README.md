# WeStride Submission Portal

ระบบส่งงานสำหรับ UXUI Bootcamp — นักเรียนส่งงานได้จากหน้าบทเรียนโดยตรง เห็นเฉพาะงานของตัวเอง
ส่วนเมนเทอร์ที่เป็น `@we-stride.com` เห็นงานของทุกคนใน Google Drive ตามเดิม

---

## ทำไมวิธีเดิมถึงกั้นไม่ได้

Google Drive ไม่มีโหมด "แชร์โฟลเดอร์แม่ แต่ให้แต่ละคนเห็นเฉพาะโฟลเดอร์ตัวเอง"
ถ้าคนหนึ่งเปิดโฟลเดอร์แม่ได้ เขาจะเห็นโฟลเดอร์ของทุกคนที่อยู่ข้างในเสมอ

การตั้งค่าปัจจุบัน (`General access: WeStride — Editor` + `Allow editors to change permissions and share`)
เท่ากับทุกคนที่มีลิงก์เป็น Editor ทั้งโฟลเดอร์ นักเรียนจึงเปิด แก้ ลบ หรือแม้แต่แชร์งานของเพื่อนต่อได้

**ทางออกคือถอดนักเรียนออกจาก Drive ทั้งหมด** แล้วให้ส่งงานผ่านตัวกลางที่มีสิทธิ์เขียนแทน
โฟลเดอร์แม่จึงถูกแชร์ให้เฉพาะกลุ่มเมนเทอร์ ส่วนนักเรียนไม่เคยมีสิทธิ์ใน Drive เลยตั้งแต่ต้น

## ติดตั้ง (ประมาณ 30 นาที)

### 1. เตรียม Google Group ของเมนเทอร์

สร้าง group ที่ <https://groups.google.com> แล้วใส่เมนเทอร์ทุกคนเข้าไป
ต่อไปเวลามีเมนเทอร์เข้า/ออก ให้จัดการที่ group อย่างเดียว ไม่ต้องมาแก้สิทธิ์โฟลเดอร์

**ตั้งชื่อให้บอกหน้าที่ของมัน** กลุ่มนี้คือบัญชีรายชื่อสิทธิ์เข้าถึง ไม่ใช่กลุ่มของทั้งคลาส
ถ้าตั้งชื่อกว้าง ๆ อย่าง "UXUI Bootcamp" อีกหลายเดือนจะมีคนเข้าใจผิดแล้วแอดนักเรียนเข้ามา
ซึ่งเท่ากับเปิดงานนักเรียนให้กันเองทันทีโดยไม่มีใครรู้ตัว

| ช่อง | ค่าที่ใช้ |
|---|---|
| Group name | `UXUI Bootcamp Mentors` |
| Group email | `uxui-mentors@we-stride.com` |
| Description | ระบุให้ชัดว่าสมาชิกกลุ่มนี้เห็นงานนักเรียนทุกคน และห้ามแอดนักเรียน |

**Privacy settings — ตั้งให้แคบทั้งหมด**

| การตั้งค่า | ค่าที่ใช้ | เหตุผล |
|---|---|---|
| Who can join group | **Only invited users** | ค่า default คือ "Anyone in the organization can join" ซึ่งแปลว่าพนักงานคนไหนก็กดเข้ากลุ่มเองแล้วได้สิทธิ์เห็นงานนักเรียนทันที |
| Who can view conversations | Group members | กลุ่มนี้ควบคุมสิทธิ์ ไม่ใช่ mailing list |
| Who can post | Group members | เหมือนกัน |
| Who can view members | Group members | เหมือนกัน |

**สมาชิก**

| ช่อง | ใส่ใคร |
|---|---|
| Group members | เมนเทอร์ทุกคน |
| Group managers | 1 คนเป็นตัวสำรอง — เผื่อ owner ไม่อยู่ จะได้ยังแอดเมนเทอร์ใหม่ได้ |
| Group owners | คนที่ดูแลคอร์ส |

Manager กับ Member **ได้สิทธิ์ใน Drive เท่ากัน** ต่างกันแค่ Manager แอด/ถอดคนออกจากกลุ่มได้เอง
คือแจกสิทธิ์เข้าถึงงานนักเรียนได้โดยไม่ผ่าน owner จึงควรมีเท่าที่จำเป็น

ตอนแอดสมาชิก ให้ติ๊ก **"Directly add members"** ไว้ ถ้าไม่ติ๊กจะกลายเป็นส่งคำเชิญ
และสิทธิ์จะยังไม่มีผลจนกว่าแต่ละคนจะกดรับ ซึ่งทำให้เมนเทอร์เปิด Drive ไม่ได้โดยไม่รู้สาเหตุ

> แนะนำให้ย้ายโฟลเดอร์แม่ไปไว้ใน **Shared Drive** ด้วย เพื่อให้ไฟล์เป็นขององค์กร
> ไม่ผูกกับบัญชีคนใดคนหนึ่ง ถ้าคนนั้นลาออก งานจะไม่หายไปด้วย
> วิธีตั้งค่าอยู่ในหัวข้อ "ตั้งค่า Shared Drive" ด้านล่าง

### 2. สร้างโปรเจกต์ Apps Script

1. เปิด <https://script.google.com> → New project
2. สร้างไฟล์ตามรายการข้างบน แล้ว copy เนื้อหาจาก repo นี้ไปวาง
   (ไฟล์ `.gs` เลือกชนิด Script, `Index.html` เลือกชนิด HTML)
3. ใน `Config.gs` ใส่ `ROOT_FOLDER_ID` — เอามาจาก URL ของโฟลเดอร์
   `https://drive.google.com/drive/folders/<ตรงนี้คือ ID>`

   ถ้าใช้ Shared Drive **อย่าใช้ ID ของตัว Shared Drive เอง** ให้สร้างโฟลเดอร์ย่อยข้างใน
   เช่น `Students` แล้วใช้ ID ของโฟลเดอร์ย่อยนั้นแทน — ทั้งชัดเจนกว่าและเผื่อที่ให้เก็บ
   Template หรือไฟล์ของทีมไว้ในไดรฟ์เดียวกันได้โดยไม่ปนกับงานนักเรียน

   วิธีดูว่าหยิบถูกตัวไหม: **ID ของ Shared Drive ขึ้นต้นด้วย `0A` ส่วนโฟลเดอร์ธรรมดาขึ้นต้นด้วย `1`**
   ถ้ายืนอยู่หน้าแรกของ Shared Drive จะได้ ID ที่ขึ้นต้น `0A` ซึ่งผิด ต้องดับเบิลคลิกเข้าไป
   ในโฟลเดอร์ `Students` ก่อนแล้วค่อยดู URL

   ใส่เฉพาะ ID ไม่ใช่ทั้ง URL และตัด `?usp=sharing` ท้ายลิงก์ทิ้งถ้ามี
4. ใส่ `MENTOR_GROUP` เป็นอีเมลของ group ที่สร้างไว้

### 3. สร้างชีต Roster

เลือกฟังก์ชัน `setupPortal` จาก dropdown ด้านบน แล้วกด **Run** หนึ่งครั้ง

ครั้งแรกจะขอสิทธิ์ → **Review permissions** → เลือกบัญชี → หน้าเตือน *"Google hasn't verified this app"*
ให้กด **Advanced** → **Go to … (unsafe)** → **Allow** หน้าเตือนนี้ปกติ เพราะเป็นสคริปต์ที่เราเขียนเอง
ไม่ได้ส่งให้ Google ตรวจสอบ

จากนั้นเปิด **Execution log** จะเห็นบรรทัด `ROSTER_SHEET_ID = ...` เอาไปใส่ใน `Config.gs` แล้ว Save

> ชีตที่ได้จะถูกสร้างไว้ใน My Drive ของคนที่รัน ให้ลากเข้าไปเก็บใน Shared Drive ด้วย
> ด้วยเหตุผลเดียวกับไฟล์งาน — ย้ายแล้วสคริปต์ยังทำงานปกติ ไม่ต้องแก้โค้ด

แล้วกรอกรายชื่อนักเรียนในแท็บ `Roster` (ขั้นนี้ทำมือ):

| code | full_name | folder_name | file_tag | email |
|---|---|---|---|---|
| *(เว้นว่าง)* | Somchai Jaidee | Somchai-Jaidee | Somchai | somchai@example.com |

- `code` เว้นว่างไว้ได้ ระบบจะออกให้ในขั้นถัดไป
- `folder_name` คือชื่อโฟลเดอร์ใน Drive ถ้าเว้นว่างจะใช้ `full_name` แปลงให้
- `file_tag` คือคำที่ต่อท้ายชื่อไฟล์ ถ้าเว้นว่างจะใช้คำแรกของ `folder_name`
- อย่าสลับลำดับหรือเปลี่ยนชื่อคอลัมน์หัวตาราง

> **โฟลเดอร์ของนักเรียนไม่ต้องสร้างเองและไม่ต้องแชร์** สคริปต์สร้างให้ตอนนักเรียนส่งงานชิ้นแรก
> โดยอ่านชื่อจาก `folder_name` และสิทธิ์สืบทอดจาก Shared Drive ลงมาให้อยู่แล้ว
> การไปกดแชร์โฟลเดอร์นักเรียนรายคนเพิ่มเองมีแต่จะเปิดช่องให้คนนอกกลุ่มเข้าถึงโดยไม่ตั้งใจ

### 5. ล็อกสิทธิ์

**ถ้าใช้ Shared Drive (แนะนำ):** ข้าม `lockDownRootFolder()` ไป — ฟังก์ชันนั้นใช้กับโฟลเดอร์
ใน My Drive เท่านั้น และจะ error ถ้าเรียกกับ Shared Drive ให้ตั้งค่าที่หน้า Shared Drive แทน
ตามหัวข้อ "ตั้งค่า Shared Drive" ด้านล่าง

**ถ้าใช้โฟลเดอร์ใน My Drive:** รัน `lockDownRootFolder()` — ฟังก์ชันนี้จะ
- ตั้งโฟลเดอร์เป็น Restricted (ปิดลิงก์สาธารณะ)
- ปิด "Allow editors to change permissions and share"
- ถอดสิทธิ์ทุกคนที่ไม่ใช่ mentor group ออก
- ใส่ mentor group เป็น Editor

### 6. Deploy web app

Deploy → New deployment → เลือก **Web app**

| ช่อง | ค่าที่ต้องเลือก | เหตุผล |
|---|---|---|
| Execute as | **Me** | ไฟล์จะเป็นของ WeStride ไม่ใช่ของนักเรียน |
| Who has access | **Anyone** | นักเรียนไม่ต้องมีบัญชี Google และ iframe ไม่ติดปัญหา cookie |

"Anyone" ในที่นี้ไม่ได้แปลว่าใครก็เข้าดูงานได้ — หน้าเว็บนี้ **เขียนอย่างเดียว ไม่มี API สำหรับอ่านงานคนอื่น**
ต้องมีรหัสถึงจะอัปโหลดได้ และรหัสเปิดได้แค่สถานะของตัวเองเท่านั้น

## ตั้งค่า Shared Drive

### สมาชิก

| ใคร | Role | เหตุผล |
|---|---|---|
| บัญชีที่เป็นเจ้าของ Apps Script | **Manager** | สคริปต์รันด้วยสิทธิ์บัญชีนี้ ต้องสร้างโฟลเดอร์และไฟล์ได้ |
| `mentors@we-stride.com` | **Contributor** | เปิดอ่านงาน ดาวน์โหลด และวางไฟล์ feedback ได้ แต่ลบงานนักเรียนไม่ได้ |
| นักเรียน | **ไม่ต้องแอดเลย** | ส่งงานผ่านพอร์ทัล ไม่ต้องมีสิทธิ์ใน Drive |

แอดเป็น **Google Group ทีเดียว** อย่าแอดเมนเทอร์ทีละคน เพราะเวลาคนเข้า/ออกจะต้องมาไล่แก้ทุก
Shared Drive ถ้าแอดเป็น group ก็จัดการที่ group ที่เดียวจบ

> ให้ **Contributor** เป็นค่าตั้งต้นก่อน ถ้าเมนเทอร์คนไหนต้องจัดระเบียบโฟลเดอร์หรือย้ายไฟล์
> ค่อยอัปเป็น Content manager เฉพาะคน — Contributor ลบงานนักเรียนทิ้งไม่ได้ ซึ่งเป็นสิ่งที่เราต้องการ

### Shared drive settings — ต้องปิด 3 ข้อ

ค่าเริ่มต้นของ Google เปิดไว้หมด ซึ่งเปิดช่องรั่วแบบเดียวกับที่เรากำลังแก้อยู่

| การตั้งค่า | ตั้งเป็น | ถ้าไม่ปิดจะเกิดอะไร |
|---|---|---|
| Allow people outside of WeStride to access files | ☐ **ปิด** | มีคนแชร์งานนักเรียนออกนอกองค์กรได้ |
| Allow people who aren't shared drive members to access files | ☐ **ปิด** | แชร์โฟลเดอร์นักเรียนรายคนให้ใครก็ได้ — ช่องโหว่ตัวเดียวกับของเดิม |
| Allow content managers to share folders | ☐ **ปิด** | เหลือแค่ Manager ที่แชร์ได้ ลดโอกาสแชร์ผิดพลาด |
| People who can download, copy, and print | ☑ **เปิดทั้งสองข้อ** | เมนเทอร์ต้องโหลด PDF ไปตรวจ |

> ปิดสองข้อแรกแล้ว **สิทธิ์เข้าถึงจะเหลือเฉพาะสมาชิกของ Shared Drive เท่านั้น**
> ซึ่งคือสิ่งที่เราต้องการพอดี — นักเรียนไม่ใช่สมาชิก จึงไม่มีทางเปิดงานของกันและกันได้เลย

### ข้อดีที่ได้เพิ่มจากการอยู่บน Shared Drive

- ไฟล์เป็นขององค์กร ไม่กินโควตาของบัญชีใครคนหนึ่ง (บัญชีเจ้าของใช้ไป 94GB แล้ว)
- คนลาออก งานไม่หายไปกับบัญชี
- มี Trash ของไดรฟ์แยก กู้ไฟล์ที่ถูกลบได้ 30 วัน

### ข้อควรระวัง

- **`lockDownRootFolder()` ใช้กับ Shared Drive ไม่ได้** จะ error เพราะ `setSharing()` และ
  `setShareableByEditors()` ไม่รองรับไฟล์ใน Shared Drive — ให้ตั้งค่าจากหน้าเว็บตามตารางข้างบนแทน
- **`FormOrganizer.gs` มีข้อจำกัดเพิ่ม** ไฟล์ที่อัปโหลดผ่าน Google Form จะไปตกใน My Drive
  ของเจ้าของฟอร์มก่อน แล้วสคริปต์ค่อยย้ายเข้า Shared Drive ซึ่งเป็นการย้ายข้ามขอบเขต
  บางองค์กรที่ตั้ง policy ห้ามย้ายไฟล์เข้า Shared Drive จะทำไม่ผ่าน
  ถ้าเจอ error ตรงนี้ให้ใช้ web app portal แทน เพราะมันเขียนลง Shared Drive ตรง ๆ ตั้งแต่แรก

## เพิ่มโมดูลใหม่

แก้แค่ `CONFIG.MODULES` ใน `Config.gs`:

```javascript
'module-02': {
  title: 'Module 2 · Information Architecture',
  folderName: 'Module-02',
  slots: [
    { id: '04', label: 'User Flow',  filePrefix: '04-user-flow' },
    { id: '05', label: 'Wireframe',  filePrefix: '05-wireframe' }
  ]
}
```

แล้วในหน้าบทเรียนโมดูล 2 เปลี่ยน iframe เป็น `?module=module-02` — Roster และรหัสเดิมใช้ต่อได้เลย

## ข้อจำกัดที่ควรรู้

- **ขนาดไฟล์** Apps Script รับ payload ได้ราว 50MB และ base64 ทำให้ข้อมูลโตขึ้น ~33%
  จึงตั้งเพดานไว้ที่ 25MB ต่อไฟล์ ถ้าต้องรับไฟล์ใหญ่กว่านี้ ให้ใช้ทางเลือก Google Form แทน
- **โควตา Drive** ไฟล์ทั้งหมดนับเข้าโควตาของบัญชีเจ้าของสคริปต์
  บัญชีนี้ใช้ไปแล้ว 94GB จึงควรวางโฟลเดอร์ไว้ใน Shared Drive
- **รหัสนักเรียน** เป็นความลับระดับ "รหัสห้องเรียน" ไม่ใช่รหัสผ่านจริง
  ถ้าหลุด คนที่ได้ไปจะส่งงานแทนได้ แต่ **เปิดดูงานของใครไม่ได้** ระบบไม่มีช่องทางอ่านไฟล์เลย
  ถ้าหลุดจริง แก้โดยเปลี่ยนรหัสในชีตแล้วส่งใหม่
- **เมนเทอร์** ยังเข้า Drive ตามปกติทุกอย่าง ไม่ต้องเรียนรู้เครื่องมือใหม่

## ทางเลือกอื่นที่พิจารณาแล้ว

| วิธี | เห็นเฉพาะของตัวเอง | โครงโฟลเดอร์เป็นระเบียบ | ฝังใน LMS ได้ | แรงที่ต้องลง |
|---|---|---|---|---|
| **Apps Script portal** (ตัวนี้) | ✅ | ✅ อัตโนมัติ | ✅ | ปานกลาง |
| Google Form + `FormOrganizer.gs` | ✅ | ✅ อัตโนมัติ | ✅ | น้อย |
| Google Form เปล่า ๆ | ✅ | ❌ Google จัดโฟลเดอร์ให้เอง | ✅ | น้อยมาก |
| แชร์โฟลเดอร์รายคนด้วยมือ | ✅ | ✅ | ❌ | สูงมาก และพลาดง่าย |
| Google Classroom | ✅ | — ไม่ใช่โครง Drive | ❌ | น้อย (ถ้า Workspace รองรับ) |
| Airtable / Tally form | ✅ | ❌ ไฟล์ไม่อยู่ใน Drive | ✅ | น้อย แต่มีค่าใช้จ่าย |

ถ้าอยากได้เร็วที่สุด ให้เริ่มจาก **Google Form + `FormOrganizer.gs`** ก่อน
แล้วค่อยย้ายมา portal ทีหลังได้ เพราะทั้งสองแบบใช้ Roster และโครงโฟลเดอร์ชุดเดียวกัน
